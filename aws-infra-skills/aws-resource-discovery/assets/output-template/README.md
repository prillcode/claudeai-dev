# Output Template Examples

This directory contains example output files generated by the aws-resource-discovery skill.

## Files

### metadata.json
Contains scan metadata including:
- AWS account ID and region
- Timestamp of scan
- AWS profile used
- Filters applied (tags, name patterns, resource types)
- Resource counts by type

### lambdas.json
Array of Lambda function configurations discovered, including:
- Function name and ARN
- Runtime and handler
- Memory, timeout, and other configurations
- Environment variables
- IAM role ARN
- VPC configuration (if applicable)
- Layers
- Tags

### dynamodb-tables.json
Array of DynamoDB table configurations discovered, including:
- Table name and ARN
- Key schema (partition key, sort key)
- Attribute definitions
- Billing mode (provisioned vs on-demand)
- Global and local secondary indexes
- Stream configuration
- Encryption settings
- Point-in-Time Recovery status
- TTL configuration
- Tags

### dependencies.json
Array of detected dependencies between resources, including:
- Source resource ARN
- Target resource ARN
- Relationship type (lambda_uses_table, eventbridge_triggers_lambda, etc.)
- Evidence for the dependency detection

## Example Scenario

These examples represent a simple order processing system with:

**Architecture**:
```
EventBridge Rule → Lambda Function → DynamoDB Table
                ↓                  ↓
           Lambda (validator) → DynamoDB (validation rules)
                ↓
           Lambda (notifier) → SNS Topic
```

**Resources**:
- 3 Lambda functions (order-processor, order-validator, order-notifier)
- 2 DynamoDB tables (orders-table, validation-rules)
- 4 IAM roles (one per Lambda + shared role)
- 2 IAM policies (DynamoDB and S3 access)
- 1 S3 bucket (order-assets)
- 2 EventBridge rules (order-created, order-validation-required)

**Dependencies Detected**:
- Lambda functions → IAM roles
- Lambda functions → DynamoDB tables
- Lambda function → S3 bucket
- EventBridge rules → Lambda functions
- IAM roles → IAM policies

## Output Schema

### Resource Schema Pattern

All resource types follow this general pattern:

```json
{
  "resource_name": "string",
  "resource_arn": "string",
  // Resource-specific properties
  "tags": {
    "key": "value"
  }
}
```

### Dependency Schema

```json
{
  "source": "arn:aws:...",
  "target": "arn:aws:...",
  "relationship": "relationship_type",
  "evidence": "human-readable explanation"
}
```

### Metadata Schema

```json
{
  "account_id": "string",
  "region": "string",
  "scan_timestamp": "ISO 8601 timestamp",
  "profile": "string",
  "filters_applied": {
    "tags": {},
    "name_pattern": "string",
    "resource_types": []
  },
  "resource_counts": {
    "resource_type": number
  }
}
```

## Notes

- All ARNs in these examples use placeholder account ID `123456789012`
- Timestamps use ISO 8601 format with UTC timezone
- Resource IDs and names follow AWS naming conventions
- Tags demonstrate common tagging strategies (project, environment, service)
- Dependencies show various detection methods (configuration, IAM policy, environment variables)
