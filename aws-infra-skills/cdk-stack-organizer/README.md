# cdk-stack-organizer

Organize generated CDK constructs into logical stacks with proper dependency management.

## Overview

`cdk-stack-organizer` is a Claude Code skill that takes CDK construct files (generated by `cdk-code-generator`) and organizes them into a complete, deployable CDK application with:
- Logical stack boundaries based on organizational strategy
- Proper cross-stack dependency handling
- Complete CDK project structure (bin/app.ts, lib/, cdk.json, etc.)
- TypeScript configuration and build setup

**Version**: 1.0 MVP

## Features

- ✅ 4 organization strategies (layer, service, environment, tags)
- ✅ Automatic cross-stack dependency detection
- ✅ Complete CDK project generation
- ✅ TypeScript compilation setup
- ✅ Best practices and conventions
- ✅ Documentation and setup instructions

## Organization Strategies

### 1. By Layer (Default - Recommended)

Organizes resources by architectural layer:

**Stacks created:**
- `IamStack` - IAM roles and policies
- `DataStack` - DynamoDB tables, S3 buckets
- `ComputeStack` - Lambda functions
- `ApiStack` - API Gateway, EventBridge rules

**Best for:**
- Serverless applications
- Clean architecture projects
- Clear separation of concerns

**Dependencies:**
```
ApiStack → ComputeStack → DataStack → IamStack
```

### 2. By Service

Groups all resources for each service together:

**Stacks created:**
- `{ServiceName}Stack` - All resources for that service
- `SharedStack` - Shared/common resources

**Best for:**
- Microservices architectures
- Multiple applications
- Service-based teams

### 3. By Tags

Groups resources based on AWS tags:

**Stacks created:**
- `{TagKey}-{TagValue}Stack` - Resources with matching tag
- `SharedStack` - Resources without tags

**Best for:**
- Tag-based resource management
- Cost allocation by project/department
- Existing tagging strategies

### 4. By Environment

*(Coming in v1.1)*

Separates resources by environment (dev/staging/prod).

## Command-Line Options

### Required Arguments

- `--input-dir DIR`: Path to cdk-code-generator output directory
- `--output-dir DIR`: Output directory for organized CDK project

### Optional Arguments

- `--strategy STRATEGY`: Organization strategy (choices: `layer`, `service`, `tags`) [default: layer]
- `--cdk-version VERSION`: Target CDK version [default: 2.0.0]
- `--stack-prefix PREFIX`: Prefix for stack names [default: none]
- `--cross-stack-refs`: Enable cross-stack references [default: true]

## Next Steps After Organization

After organizing your stacks:

### 1. Install Dependencies

The generated CDK project is a TypeScript project that requires installing dependencies:

```bash
cd my-cdk-app

# Using npm
npm install

# Or using pnpm (recommended)
pnpm install
```

### 2. Build the Project
```bash
# Using npm
npm run build

# Or using pnpm
pnpm run build
```

### 3. Review Generated Code
- Check stack organization in `lib/`
- Review cross-stack dependencies
- Update TODO comments in stack files
- Copy/reference construct files from original location

### 4. Synthesize CloudFormation
```bash
cdk synth
```

### 5. Preview Changes
```bash
cdk diff
```

### 6. Bootstrap CDK (if needed)
```bash
cdk bootstrap aws://ACCOUNT-NUMBER/REGION
```

### 7. Deploy Stacks
```bash
# Deploy all stacks
cdk deploy --all

# Or deploy specific stack
cdk deploy DataStack

# For existing resources, use cdk-import-config-generator next
```

> **Note**: The Python skills themselves require no installation (pure Python stdlib), but the **generated CDK TypeScript project** needs npm/pnpm to install CDK dependencies.

## How It Works

1. **Load Input**: Reads metadata and constructs from cdk-code-generator output
2. **Analyze**: Examines construct types, names, tags to determine organization
3. **Group**: Groups constructs into logical stacks based on strategy
4. **Dependencies**: Analyzes and creates cross-stack dependencies
5. **Generate**: Creates CDK project structure with all files
6. **Document**: Generates README and metadata

## Troubleshooting

### Issue: "Input directory not found"
**Solution**: Verify the path to your cdk-code-generator output directory.

### Issue: "No constructs found"
**Solution**: Ensure input directory has `constructs/` folder with .ts files.

### Issue: "Invalid strategy"
**Solution**: Use one of: `layer`, `service`, `tags`

### Issue: "Circular dependency detected"
**Solution**: Review the warning, may need manual intervention. Consider refactoring to shared stack.

### Issue: Generated code doesn't compile
**Solution**:
- Run `npm install` or `pnpm install` first
- Check for TODO comments that need updates
- Ensure construct imports are correct
- Copy construct files to appropriate location

## Workflow Integration

**Full workflow:**
1. `aws-resource-discovery` → Discovers AWS resources
2. `cdk-code-generator` → Generates CDK constructs
3. **`cdk-stack-organizer`** → Organizes into stacks ← **YOU ARE HERE**
4. `cdk-import-config-generator` → Creates import configs
5. `cdk import` → Imports resources into CloudFormation

**Upstream (Input from):**
- `cdk-code-generator`: Provides the constructs to organize

**Downstream (Output to):**
- `cdk-import-config-generator`: Takes organized project for import configs
- Your CDK deployment pipeline
