# cdk-stack-organizer

Organize generated CDK constructs into logical stacks with proper dependency management.

## What This Skill Does

Takes CDK construct files generated by `cdk-code-generator` and organizes them into a complete, deployable CDK application with:
- Logical stack boundaries based on organizational strategy
- Proper cross-stack dependency handling
- Complete CDK project structure (bin/app.ts, lib/stacks, cdk.json, etc.)
- TypeScript configuration and dependencies

## When to Use This Skill

Use this skill **after** running `cdk-code-generator` to organize the generated constructs into a deployable CDK project.

**Trigger phrases:**
- "organize the generated CDK code into stacks"
- "create a CDK project from the generated constructs"
- "organize by layer/service/environment"
- "organize constructs into logical stacks"

## Input Requirements

1. **Generated CDK constructs directory** (from cdk-code-generator)
   - Must contain `constructs/` directory with TypeScript files
   - Must contain `metadata.json`
   - Should contain `dependencies.json` (optional but recommended)

## Organization Strategies

### 1. By Layer (Default - Recommended)
Organizes resources by architectural layer:
- **Data Layer Stack**: DynamoDB tables, S3 buckets
- **Compute Layer Stack**: Lambda functions
- **API Layer Stack**: API Gateway, EventBridge rules
- **IAM Stack**: IAM roles and policies

**Best for:** Clean architecture, clear separation of concerns

### 2. By Service
Groups all resources belonging to the same service/application together:
- Each service gets its own stack
- Detected from resource names or tags

**Best for:** Microservices architectures, multi-service applications

### 3. By Environment
Organizes for multi-environment deployments:
- Creates stack structure for dev/staging/prod
- Same resources in each environment

**Best for:** Multi-environment deployments with consistent infrastructure

### 4. By Tags
Groups resources based on AWS tags:
- Uses tags from original AWS resources
- Shared resources go in a common stack

**Best for:** Tag-based resource management, custom groupings

## How Claude Should Invoke This Skill

When the user requests stack organization:

1. **Locate the input directory** (generated constructs from cdk-code-generator)
2. **Determine organization strategy** from user request or use default (by-layer)
3. **Execute the organize.py script**:
   ```bash
   python scripts/organize.py \
     --input-dir PATH_TO_CDK_GENERATED \
     --output-dir PATH_TO_OUTPUT \
     --strategy STRATEGY_NAME
   ```
4. **Report the results** to the user with next steps

## Command-Line Interface

### Required Arguments
- `--input-dir DIR`: Path to cdk-code-generator output directory
- `--output-dir DIR`: Output directory for organized CDK project

### Optional Arguments
- `--strategy STRATEGY`: Organization strategy (choices: `layer`, `service`, `environment`, `tags`) [default: layer]
- `--cdk-version VERSION`: Target CDK version [default: 2.0.0]
- `--stack-prefix PREFIX`: Prefix for stack names [default: none]
- `--cross-stack-refs`: Enable cross-stack references [default: true]

### Examples

**Organize by layer (default):**
```bash
python scripts/organize.py \
  --input-dir ../cdk-code-generator/cdk-generated \
  --output-dir ./my-cdk-app
```

**Organize by service:**
```bash
python scripts/organize.py \
  --input-dir ../cdk-code-generator/cdk-generated \
  --output-dir ./my-cdk-app \
  --strategy service
```

**With stack prefix:**
```bash
python scripts/organize.py \
  --input-dir ../cdk-code-generator/cdk-generated \
  --output-dir ./my-cdk-app \
  --strategy layer \
  --stack-prefix MyApp
```

## What This Skill Generates

1. **CDK Application Structure**
   - Proper TypeScript project setup
   - CDK configuration (cdk.json)
   - Build configuration (tsconfig.json)
   - Dependencies (package.json)

2. **Stack Files**
   - One or more stack files in `lib/`
   - Each stack imports and instantiates relevant constructs
   - Proper dependency handling between stacks

3. **App Entry Point**
   - `bin/app.ts` that instantiates all stacks
   - Proper stack dependencies and deployment order

4. **Documentation**
   - README with setup and deployment instructions
   - organization-metadata.json with stack details

## Error Handling

Common issues and solutions:

- **"Input directory not found"**: Check path to cdk-code-generator output
- **"No constructs found"**: Ensure input directory has constructs/ folder with .ts files
- **"Invalid strategy"**: Use one of: layer, service, environment, tags
- **"Circular dependency detected"**: Report to user, may need manual intervention
